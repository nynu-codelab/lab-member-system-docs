# 实验室成员管理系统 - 测试用例

> 文档版本：V1.1

## 1. 测试方式

可使用：

- Swagger
- Apifox
- Postman
- JUnit
- MockMvc
- 浏览器手动操作前端页面

建议：Swagger/Apifox 做接口功能测试，JUnit/MockMvc 做后端自动化测试，浏览器手动验证前端页面。

| 编号 | 场景 | 预期 |

| LIST-001 | 默认查询 | 200，page=1，pageSize=10 |

| LIST-007 | 多条件组合 | 所有条件同时满足 |

## 7. 边界测试

| 编号 | 场景 | 要求 |
| --- | --- | --- |
| EDGE-001 | 超长 name | 400 或合理处理 |
| EDGE-002 | 超长 studentNo | 不允许产生未处理 500 |
| EDGE-003 | page=0 | 合理校验 |
| EDGE-004 | pageSize=0 | 合理校验 |
| EDGE-005 | page=-1 | 合理校验 |
| EDGE-006 | pageSize=-1 | 合理校验 |

## 8. 数据一致性

### DATA-001

新增 → 查询，查询结果与新增数据一致。

### DATA-002

修改 → 查询，查询结果为修改后的数据。

### DATA-003

删除 → 查询，必须返回 404。

## 9. 自动化测试要求

执行：

```bash
mvn test
```

至少覆盖：

### Service

- 正常新增
- 重复学号
- 查询不存在
- 修改不存在
- 删除不存在

### Controller

- 新增成功
- 参数错误
- 查询成功
- 查询不存在
- 修改成功
- 删除成功

## 10. 前端测试用例

通过浏览器手动验证，前后端联调环境（前端 dev server + 后端 8080）。

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| FE-001 | 列表页可访问 | 页面加载并展示成员数据 |
| FE-002 | 新增：正常提交 | 保存成功，列表出现新成员 |
| FE-003 | 新增：name 为空 | 前端拦截并提示，不发起请求 |
| FE-004 | 新增：studentNo 为空 | 前端拦截并提示 |
| FE-005 | 新增：gender 非 0/1/2 | 前端拦截并提示 |
| FE-006 | 新增：phone 非法格式 | 前端拦截并提示 |
| FE-007 | 新增：学号重复（后端 400） | 页面展示后端 message（如“学号已存在”） |
| FE-008 | 列表筛选：name=张 | 列表仅展示姓名含“张”的成员 |
| FE-009 | 列表筛选：grade=2023 | 列表仅展示 2023 级成员 |
| FE-010 | 分页：page=2&pageSize=5 | 展示第二页数据 |
| FE-011 | 编辑：点击编辑 | 表单回显该成员原数据 |
| FE-012 | 编辑：保存成功 | 列表展示修改后的数据 |
| FE-013 | 删除：二次确认取消 | 不删除，成员仍在列表 |
| FE-014 | 删除：确认删除 | 删除成功，列表不再出现该成员 |
| FE-015 | 后端 404（查询不存在成员） | 页面提示“成员不存在” |
| FE-016 | 后端 500 | 页面提示“系统异常” |
