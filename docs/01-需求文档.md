# 实验室成员管理系统 - 需求文档

> 文档版本：V1.1  
> 项目类型：实验室新人入门项目（前后端）

## 1. 项目背景

为了规范实验室成员信息管理，同时帮助新成员熟悉完整的软件开发流程，需要开发一个简单的实验室成员管理系统。

系统主要用于维护实验室成员的基础信息，包括姓名、学号、性别、年级、专业、手机号、邮箱和成员状态。

本项目重点训练：需求分析、数据库设计、RESTful API、前端开发、前后端联调、参数校验、异常处理、测试和 Git 协作。

## 2. 项目目标

完成一个可独立运行的前后端项目：后端提供成员管理 RESTful API（新增、查询、修改、删除，支持分页与条件查询），前端提供成员管理页面并调用后端接口完成全流程操作，覆盖参数校验、异常处理、API 文档和自动化测试。

## 3. 项目范围

### 3.1 V1.1 必须实现

- 新增成员
- 查询成员详情
- 分页查询成员
- 条件查询成员
- 修改成员
- 删除成员
- 前端成员管理页面（列表、新增、编辑、删除）

### 3.2 V1.1 不要求

登录、注册、JWT、权限管理、Redis、MQ、文件/图片上传、Excel 导入导出、邮件、短信、微服务。

如自行实现可作为加分项，但不得影响基础功能。

## 4. 用户角色

V1.1 只有“实验室管理员”。暂不实现真实登录和权限认证。

## 5. 成员信息

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | ---: | --- |
| id | Long | 否 | 系统自动生成 |
| name | String | 是 | 姓名 |
| studentNo | String | 是 | 学号，唯一 |
| gender | Integer | 是 | 0未知/1男/2女 |
| grade | String | 是 | 年级 |
| major | String | 是 | 专业 |
| phone | String | 否 | 手机号 |
| email | String | 否 | 邮箱 |
| status | Integer | 是 | 0离开/1正常 |
| createTime | DateTime | 否 | 创建时间 |
| updateTime | DateTime | 否 | 更新时间 |

## 6. 功能需求

### 6.1 新增成员

业务规则：

1. name 不能为空
2. studentNo 不能为空
3. studentNo 不能重复
4. gender 只能为 0、1、2
5. grade 不能为空
6. major 不能为空
7. status 只能为 0、1
8. phone 填写时必须符合手机号格式
9. email 填写时必须符合邮箱格式

### 6.2 查询成员

支持：

- 根据 ID 查询详情
- 分页查询
- 按姓名模糊查询
- 按学号查询
- 按年级查询
- 按状态查询
- 多条件组合查询

不存在的成员返回 HTTP 404。

### 6.3 修改成员

1. ID 不存在返回 404
2. 参数必须校验
3. studentNo 不能与其他成员重复
4. updateTime 必须更新

### 6.4 删除成员

1. 成员存在时删除成功
2. 成员不存在返回 404
3. 删除后查询该成员必须返回 404
4. 删除后列表中不得出现该成员

### 6.5 前端页面需求

V1.1 必须提供一个简单的前端管理页面，通过调用后端 API（见 `docs/03-接口文档.md`）完成成员管理，覆盖后端全部 CRUD 功能。

#### 页面清单

1. **成员列表页**
   - 分页表格展示成员：id、姓名、学号、性别、年级、专业、手机号、邮箱、状态、操作
   - 条件筛选：姓名（模糊）、学号、年级、状态
   - 分页控件：页码、每页条数
   - 操作：新增、编辑、删除
2. **新增成员表单**（页面或弹窗）
   - 字段与接口文档一致：name、studentNo、gender、grade、major、phone、email、status
   - 前端校验规则与后端一致：必填（name / studentNo / gender / grade / major / status）、枚举（gender ∈ {0,1,2}、status ∈ {0,1}）、phone / email 填写时格式校验
3. **编辑成员表单**：回显原数据，保存后刷新列表
4. **删除确认**：删除需二次确认，成功后列表移除

#### 交互要求

- 调用 `/api/members` 系列接口，按统一返回结构 `code / message / data` 处理：`code=200` 成功；`code=400` 提示 `message`（如学号重复）；`code=404` 提示“成员不存在”；`code=500` 提示“系统异常”
- 列表分页与筛选通过 query 参数传给后端，由后端分页（禁止前端全量拉取后内存分页）
- 开发环境使用 Vite 代理 `/api` → `http://localhost:8080`

#### 技术栈（建议）

- Vue 3 + Vite + TypeScript
- UI 组件库可选用 Element Plus
- HTTP 请求使用 fetch 或 axios

#### 前端质量要求

- 组件拆分合理、命名清晰、代码可读
- 表单校验完整，与后端校验规则一致
- 不强制前端自动化测试，但所有功能必须手动验证通过

#### 加分项（不影响基础功能）

- 前端自动化测试
- 响应式布局 / 移动端适配

## 7. 统一返回结构

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

参数错误：

```json
{
  "code": 400,
  "message": "参数错误",
  "data": null
}
```

数据不存在：

```json
{
  "code": 404,
  "message": "成员不存在",
  "data": null
}
```

服务端异常：

```json
{
  "code": 500,
  "message": "系统异常",
  "data": null
}
```

## 8. HTTP 状态码

| 状态码 | 含义 |
| ---: | --- |
| 200 | 成功 |
| 400 | 参数错误或业务参数不合法 |
| 404 | 数据不存在 |
| 500 | 服务端异常 |

- Java 17+
- Spring Boot 3.x

## 12. 完成标准

以下流程必须完整可执行：

创建成员 → 查询成员 → 修改成员 → 查询修改结果 → 删除成员 → 再次查询确认不存在；并通过前端页面完整走通一遍上述流程。
